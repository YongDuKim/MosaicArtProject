# 色比較の検証

設定の範囲・初期値は[使い方](../user/usage.md#色比較とばらつき)、距離と候補選択の定義は[アルゴリズム解説](algorithm.md#色比較と候補選択)を参照。

## 確認環境

Linux x86_64 (WSL2) の Chromium 149.0.7827.55 で、`npm run dev` のアプリを Playwright から操作して確認する。検証用の Playwright と Color.js はアプリの依存に含めない。画像処理はローカルのブラウザ内で実行し、アプリから外部ホストへのリクエストを遮断した状態でも動作することを確認済み。

確認済みの項目:

- RGB の初期選択、両方式のばらつきの範囲・刻み・初期値、切り替えて戻した際の調整値の保持
- UI で選んだ方式と許容差が Worker に渡ること、方式を切り替えて繰り返し生成できること
- 同一入力で、ばらつき0・回転 OFF・色補正0%の RGB を再生成した際のタイル配置の一致と、Oklab での配置の違い
- 両方式でばらつき・回転・色補正を有効にした生成、JPG と PNG の出力
- 幅390pxでの表示。これはレイアウトの確認であり、iOS Safari の確認ではない

**iOS Safari、macOS Safari、Firefox は未確認。** iOS Safari の実機では、画像と素材を読み込んで両方式で生成し、切り替え後の再生成と、ばらつき・回転・色補正を有効にした生成を確認する必要がある。デスクトップの結果から iOS のキャンバス上限やメモリ制約への適合は判定できない。

## 実画像の比較条件

[scikit-image v0.25.2 の公開サンプル](https://github.com/scikit-image/scikit-image/tree/v0.25.2/skimage/data)の `astronaut.png`、`coffee.png`、`chelsea.png`、`rocket.jpg` を使用する。各画像の左上を起点に、短辺を5分割した正方形を25枚切り出し、64px角に縮小した計100枚を素材とする。平均色の取得とモザイク生成にはアプリの処理を使用する。

比較は64×64セル、タイル解像度8px、回転 OFF、色補正0%、PNG 出力に揃える。同じ元画像・素材・グリッドで、RGB と Oklab のばらつき0、および正のばらつきを比較する。元画像はこの比較用グリッドへ縮小するため、正方形でない元画像は比較図では縦横比が変わる。UI の通常生成では元画像の縦横比に応じてグリッド数を決める。

素材条件は次の3種類とする。

- 混合: 100枚すべて。元画像は astronaut と coffee
- 青系: 平均 RGB の B が R と G の両方より大きい22枚。元画像は rocket
- 明暗の幅が狭い素材: 平均色を Oklab に変換した L が0.45〜0.60の42枚。元画像は astronaut

## ばらつきの調整根拠

次の値は1回の生成での使用種類数と、セル目標色から選ばれたタイル代表色への平均 Oklab 距離である。正のばらつきには乱数を使用するため、数値は生成ごとに変動する。この距離は代表色の比較指標であり、写真の模様や輪郭を含む見た目全体の品質指標ではない。

| 元画像 / 素材          | ばらつき0     | 0.01          | 0.02          | 0.05           | 0.1            |
| ---------------------- | ------------- | ------------- | ------------- | -------------- | -------------- |
| astronaut / 混合       | 83種 / 0.0485 | 97種 / 0.0498 | 98種 / 0.0530 | 100種 / 0.0683 | 100種 / 0.1042 |
| coffee / 混合          | 56種 / 0.0261 | 62種 / 0.0279 | 66種 / 0.0321 | 74種 / 0.0502  | 90種 / 0.0839  |
| rocket / 青系          | 22種 / 0.0276 | 22種 / 0.0294 | 22種 / 0.0337 | 22種 / 0.0496  | 22種 / 0.0727  |
| astronaut / 明暗が狭い | 33種 / 0.1808 | 40種 / 0.1826 | 42種 / 0.1911 | 42種 / 0.2066  | 42種 / 0.2361  |

生成画像では、0.01で近い色のタイルを分散させながら顔やカップの明暗を保てる。0.02以上では、使用種類数の増加とともに色・明暗のちらつきが増えるため、初期値は小さい側を採る。上限は、元の色への忠実さを下げても写真の種類を増やす調整を可能にする値とする。青系や明暗が狭い素材では、色比較方式だけで不足する色を補うことはできない。

ばらつき0での平均 L 誤差は、RGB / Oklab の順に astronaut・混合が0.0396 / 0.0367、coffee・混合が0.0223 / 0.0167、rocket・青系が0.0216 / 0.0193だった。この比較では Oklab の方がセル代表色の明るさに近づくが、すべての画像や素材での見た目の改善を保証するものではない。

## 処理時間

元画像は512×512pxの astronaut。4枚の公開サンプルをそれぞれ10×10に切り出した400枚の64px角素材から、等間隔のインデックスで25・100・400枚を選ぶ。タイル解像度8px、回転 OFF、色補正0%、JPG 原寸出力で比較する。各条件を1回ウォームアップし、RGB と Oklab の実行順を交互にした5回の中央値を使う。

Worker のリクエスト送信から完了通知までを測定し、生成準備・配置・エンコードを含める。素材読み込みと送信用 ImageBitmap のコピー作成は含めない。単位は ms。

| 素材数 | グリッド | ばらつき       | RGB    | Oklab  |
| ------ | -------- | -------------- | ------ | ------ |
| 25     | 102×102  | 0              | 33.2   | 34.3   |
| 25     | 102×102  | 各方式の初期値 | 37.7   | 42.3   |
| 100    | 102×102  | 0              | 60.6   | 67.6   |
| 100    | 102×102  | 各方式の初期値 | 80.9   | 91.2   |
| 400    | 256×256  | 0              | 697.7  | 842.5  |
| 400    | 256×256  | 各方式の初期値 | 1238.6 | 1509.8 |

この環境では Oklab の生成時間は RGB の約1.03〜1.22倍だった。変換と小数座標での比較を含む方式全体の差であり、色変換だけの所要時間ではない。400枚・256×256セル・ばらつきありで、描画を除いた比較色の準備とタイル選択の中央値は RGB が1043.9ms、Oklab が1310.8ms。端末や素材数によって変わるため、iOS の処理時間は実機で確認する。
