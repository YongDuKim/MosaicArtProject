# モザイク生成アルゴリズム

実装は `src/lib/mosaic.ts`。

1. 入力画像を `x` (既定5) で割ったグリッドに分割
2. 各セルの代表色とタイルの代表色を、選択された色空間で比較する。「タイルのばらつき」に応じて近い色の候補から1枚選ぶ ([色比較と候補選択](#色比較と候補選択))。タイルは 256px で保持し、貼り付け前に `n` px へ段階的縮小する
3. 0/90/180/270 度のランダム回転で貼り付け (OFF 可)
4. 色補正スライダーで、ディテールを保ったままセル目標色へ色シフト
5. タイル解像度 `n` は偶数のみ。奇数だとタイル境界が JPEG のクロマ格子 (4:2:0 の2px) とずれ、原寸 JPG のファイルサイズが1割ほど増える (実測: n=25 と 27 が、24・28・32 より1ピクセルあたり 6〜10% 大きい)
6. 出力サイズは「グリッド数 × タイル解像度 `n` (既定24) px」。端末のキャンバス上限を超える場合は `n` を自動縮小する (このときも偶数に切り下げる。上限値は [architecture.md の設計原則](architecture.md) を参照)
7. 出力キャンバスを Worker 内で JPG (既定) または PNG にエンコードする。JPG の品質は `src/lib/format.ts` の `JPEG_QUALITY` 固定。JPG は書き出し解像度のプリセット (低 2,048px / 中 4,096px / 高 縮小なし) に従い、エンコード直前に段階的縮小で長辺を合わせる。PNG は常に原寸

## 色比較と候補選択

`src/lib/colorComparison.ts` は色比較方式と sRGB → Oklab 変換を扱い、`src/lib/colorUtils.ts` は同一色空間の3成分に対する距離計算と選択を扱う。色比較方式は仕上がりの評価方針とは独立したパラメータである。設定の範囲・初期値と操作方法は[使い方](../user/usage.md#色比較とばらつき)を参照。

セルの代表 RGB 色は、入力画像をグリッドサイズへ縮小した各ピクセルから取得する。タイルの代表 RGB 色は、読み込み時に算出した平均色を使う。Oklab ではこの同じ代表 RGB 色を0〜1へ正規化し、sRGB の線形化後に [Oklab の変換式](https://bottosson.github.io/posts/oklab/#converting-from-linear-srgb-to-oklab)を適用する。各画素を Oklab に変換してから平均する処理ではない。

Worker 内で生成準備時にタイルの Oklab 値をまとめて計算し、セルの代表色はセルごとに1回だけ変換する。描画と色補正には元の RGB 値を使うため、Oklab の比較座標と分けて保持する。RGB 選択時はこの変換を行わない。

最近傍は RGB では `ΔR² + ΔG² + ΔB²`、Oklab では `ΔL² + Δa² + Δb²` が最小のタイルとする。ばらつきが0なら乱数を使わず最近傍を選び、同距離の場合は配列の先頭側を優先する。

ばらつきが正なら、目標セルから各候補へのユークリッド距離を `d`、最小距離を `d_min` として、`d ≤ d_min + 許容差` の候補から一様ランダムに選ぶ。許容差は二乗距離ではなく、選択した色空間の距離の単位である。候補は元の順序を保ち、候補が1枚でも乱数を1回消費する。回転が有効なら、その後に回転用の乱数を1回消費する。この順序により、RGB 選択時は同じ入力・設定・乱数列から同じタイル選択と回転を再現する。

UI は方式別のばらつきを保持し、Worker には選択中の方式とその許容差を渡す。方式間で数値を換算したり、別の方式の値を使い回したりしない。
